# v0.2.5

Engine stabilization for the 0.2 line. This release closes the [[Dispatch Mesh milestone plan#0.2.x — engine stabilization|0.2.x]] items that the 0.3 tray builds on.

## What shipped

- [[Task - TASK00001 - Close remaining 0.2.x stabilization gaps|TASK00001]]: six-state workspace status and per-session stages, offline detection and locale-independent Git failure classification, persisted and actionable AI-summary failures, a split between quota and rate-limit responses on HTTP 429, regression tests for interrupted publication and renames, and storage and recovery documentation.
- [[Story - US00002 - Local engine control interface for the tray host|US00002]]: the in-process engine interface for desktop hosts (`Runner::start` / `RunnerHandle` with published status snapshots), with CLI commands working while it runs and a shutdown that saves local work.

Governing decisions: [[ADR-0009 — Embed the engine with a runner handle and published status]] (accepted) and [[ADR-0010 — Report workspace status and session stages separately]].

## Not in this release

- [[Story - US00001 - Tray icon and status window host|US00001]]: the tray application, planned for v0.3.0. It is still in `Backlog` with open questions, and it consumes the interface shipped here.
- [[Task - TASK00002 - Choose the Git backend before bundling Git|TASK00002]]: the Git backend choice, planned for v0.4.0. It is still in `Backlog`; this release continues to require Git on `PATH`.

## Notes

- **The `status` values changed.** `waiting_to_sync` no longer appears. The summary is one of `needs_attention`, `offline`, `saved_locally`, `draft_uploaded`, `waiting_for_finalization` or `synced`, with a top-level `reason` and a `stage` per session. Scripts that parse `status` must be updated.
- **Local state gains defaulted fields** (`uploaded`, `offline`, `summary_failure`). There is no migration step. 0.2.4 can still read the state, and the remote format is unchanged, so 0.2.4 and 0.2.5 clients interoperate.
- **A second `run` on the same workspace is refused** with "Mesh is already running for this workspace", as before. Shutdown now waits up to 10 s for a briefly held workspace lock instead of failing.
- **The library API** (`dispatch_mesh::runner`) serves the planned tray and is not yet a stable public crate surface.
