## Dispatch Mesh 0.2.5: engine stabilization

This release closes the remaining [0.2.x engine-stabilization](https://github.com/kaimys/dispatch-mesh-llm-wiki/blob/main/02_Product/Dispatch%20Mesh%20milestone%20plan.md) work. You can now tell a draft upload apart from publication on `main`, see why an operation failed, and embed the engine in-process ahead of the 0.3 tray application.

### What's new

**Clearer status and actionable failures** ([TASK00001](https://github.com/kaimys/dispatch-mesh-llm-wiki/blob/main/05_Requirements/Tickets/Task%20-%20TASK00001%20-%20Close%20remaining%200.2.x%20stabilization%20gaps.md))

- `status` reports one workspace summary, `needs_attention`, `offline`, `saved_locally`, `draft_uploaded`, `waiting_for_finalization` or `synced`, plus a `reason` and a per-session `stage`.
- Offline is detected from connection-level Git failures and reported on its own. Classification works the same on every system language.
- AI-summary failures are saved and shown in `status`. On HTTP 429, a temporary rate limit is told apart from exhausted quota or billing. Publication continues with a factual local message.
- New regression tests cover interrupted publication and renames. The README now documents storage growth and recovery procedures.

**An engine interface for desktop hosts** ([US00002](https://github.com/kaimys/dispatch-mesh-llm-wiki/blob/main/05_Requirements/Tickets/Story%20-%20US00002%20-%20Local%20engine%20control%20interface%20for%20the%20tray%20host.md))

- The run loop now lives in the library. `dispatch_mesh::runner::Runner::start` runs the engine on a background thread and returns a handle that publishes status snapshots whenever they change. `stop()` saves local work without waiting for pending network or AI requests.
- CLI `status`, `session finish` and `intent` keep working while an engine runs. A second runner on the same workspace is refused with "Mesh is already running for this workspace".
- Stopping `run` with Ctrl+C now waits briefly for a busy workspace lock instead of exiting without the final save.

Design records: [ADR-0009: Embed the engine with a runner handle and published status](https://github.com/kaimys/dispatch-mesh-llm-wiki/blob/main/07_Engineering/Decisions/ADR-0009%20%E2%80%94%20Embed%20the%20engine%20with%20a%20runner%20handle%20and%20published%20status.md) · [ADR-0010: Report workspace status and session stages separately](https://github.com/kaimys/dispatch-mesh-llm-wiki/blob/main/07_Engineering/Decisions/ADR-0010%20%E2%80%94%20Report%20workspace%20status%20and%20session%20stages%20separately.md)

### ⚠️ Breaking change

`status` no longer reports `waiting_to_sync`. Scripts that parse `status` must handle the six summary values above.

### Upgrading

- No migration step is needed. Local state gains fields with defaults, and 0.2.4 can still read it.
- The remote format is unchanged, so 0.2.4 and 0.2.5 clients can share a repository.
- Stop a running `run` with Ctrl+C before replacing the binary.

### Not in this release

- The tray application ([US00001](https://github.com/kaimys/dispatch-mesh-llm-wiki/blob/main/05_Requirements/Tickets/Story%20-%20US00001%20-%20Tray%20icon%20and%20status%20window%20host.md)) is planned for 0.3.0 and builds on the engine interface shipped here.
- A bundled Git backend ([TASK00002](https://github.com/kaimys/dispatch-mesh-llm-wiki/blob/main/05_Requirements/Tickets/Task%20-%20TASK00002%20-%20Choose%20the%20Git%20backend%20before%20bundling%20Git.md)) is planned for 0.4.0. Git must still be on `PATH`.
- `dispatch_mesh::runner` is not yet a stable public library API.
